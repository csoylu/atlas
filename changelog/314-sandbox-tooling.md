## Changed · #314 · ui-check, the screenshot scripts, the tests and the how-tos now work inside the agent sandbox

ui-check starts its own throwaway engine on a seeded database in `$TMPDIR` (no lsof, no live data) and drives Playwright's `chrome-headless-shell --no-sandbox` (installed when missing; `ATLAS_CHROME` still overrides); e2e uses the same browser. Hard-coded `/tmp` paths in scripts are `$TMPDIR`. The tests pass with paths that contain a space (the sandbox's `$TMPDIR` does) and a few of them skip by name where the sandbox refuses `ps`/`pgrep`, `osascript` or a long unix-socket path. New `scripts/test/sandbox-run.ts` runs a command as an agent runs it. CLAUDE.md and docs/howtos.md drop the live-data how-tos, mark `npm run desktop`, orb-check and `install:mac` as Master only, and get a « Sandbox » section (what is readable and writable, internet levels, `GH_TOKEN`, how to tell a denial from a bug). The label check (OCR) of ui-check runs inside the sandbox too (Vision's cache goes to the shell's own home with `CFFIXED_USER_HOME`). The engine's `screenshot` tool is unchanged. No migration.
