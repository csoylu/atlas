## Changed · #223 · Each pull request now adds its changelog entry as its own file in changelog/, so parallel pull requests no longer conflict on CHANGELOG.md

A PR adds exactly one file `changelog/<task>-<slug>.md` whose first line is `## Fixed|Added|Changed|Breaking · #task · One plain sentence`, and changes no other changelog file (CI on the push to main and the QA gate refuse anything else). The order of the entries, and so the version, comes from the order the files reached main in git history (`git log --first-parent`); the entries from before are frozen in `changelog/history.md` (the former CHANGELOG.md), so every past version stays the same. `node scripts/release/changelog.mjs full` prints the whole changelog, newest first with each version, and each GitHub release now carries it as `CHANGELOG.md`. The changelog-only auto-rebase of the QA gate (#188, #195) is gone: there is nothing left to conflict on.
