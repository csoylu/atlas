## Added · #315 · The engine side of the shared browser: one browser tab per chat or task, kept across restarts; the pane that shows it comes with #306, so nothing changes on screen yet.

- Desktop app: each tab is a Chromium view in the Atlas window, with a browser profile per workspace (project × agent: cookies and logins stay with that agent in that project) and the workspace's internet level applied through the engine's allow-list proxy. A refused page says why (« example.com is not in this workspace's allowed hosts », « This workspace is offline »). The agent's own dev server on localhost always opens.
- Pages are treated as hostile: every permission is denied (microphone, camera, notifications, location, devices), WebRTC sends no UDP past the proxy, and a page can hand only `mailto:` and `tel:` links or an http(s) download to the system, right after your own click in it. Anything else (`smb:`, `file:`, app schemes) is refused and the tab says why.
- Master's own pane (`master`) for links clicked outside a chat: its own profile, no proxy, no agent.
- One input owner per tab: while the agent has it, your clicks and keys in the page are blocked; take control and the agent's calls get « Master is using the browser ». The agent tools come with S7.
- Only http and https pages open in the pane. The routing rule of the design (§3.2) is in `linkTarget` (shared): ⌘-click, other schemes, downloads and sign-in pages stay in the system browser. Links keep opening in the system browser until the pane UI (#306) uses it.
- API: `GET /api/browser`, `GET /api/browser/tabs[/:chat]`, `POST /api/browser/tabs/:chat/open | nav | owner`, `DELETE /api/browser/tabs/:chat`, `PUT /api/browser/view` (the tab on screen and its bounds); WebSocket `browser.updated` and `browser.closed`. Without the desktop app (dev, server mode) `GET /api/browser` says the pane is unavailable.
- Tests: the engine against a fake browser host, and an Electron e2e (`e2e/tests/browser-electron.spec.ts`): a tab opens and comes back after a restart, two agents share no cookie, a host outside the allow-list is refused, your input is blocked while the agent has the tab, a page cannot open `smb:` or `file:` on the system, permissions are denied, WebRTC leaks no UDP.
