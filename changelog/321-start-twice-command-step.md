## Fixed · #321 · A command step being checked out is no longer cut off or left without its worktree when the workflow engine's start runs again

`workflows.start()` treated a command step this engine had already started (cloning, fetching, creating its worktree, before the process existed) as one a stopped engine left: it deleted every step worktree, so the step ended « couldn't run: can't check out … » and waited a minute for its automatic retry (the crash test failed on this in CI, #321). `start()` now leaves steps and worktrees of the running engine alone. A command was never run twice by this: the step is stored as running before the process starts, and a restart marks it cut off and never retries it by itself. In the app, `start()` runs once at boot, before any run, so only the crash test's child engine (which starts it late) hit the window. No migration.
